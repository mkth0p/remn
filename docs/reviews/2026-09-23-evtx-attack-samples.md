> The rest of this page is the analysis as it was written before the fixes.

Every EVTX file of [EVTX-ATTACK-SAMPLES](https://github.com/sbousseaden/EVTX-ATTACK-SAMPLES) (commit 4ceed2f, 278 files, 37,364 events) was parsed by REMN and run through its rules as a one-file case with the default case settings. That is what a visitor to the public site gets: the browser rule engine, with the core rules and the two SigmaHQ packs that are on by default (`sigma-windows`, `sigma-emerging-threats`; 97 + 2,682 event rules). The hunting pack, off by default, was run separately. Hayabusa, which the public server also runs, was not part of this run.

Each sample was then judged by one reviewer (what attack it records, whether a rule that fired actually identifies it, and if not, why), and every verdict was re-checked by an independent skeptic who tried to refute it; 14 verdicts changed. Where the server's SQL engine and the browser engine disagreed, the difference was traced to its cause in the code and reproduced.

Where REMN is strong: process-creation and process-access behaviour recorded by Sysmon (Mimikatz and LSASS access, UACMe and most UAC bypasses, LOLBins, Office and script-host chains, PsExec and service-based lateral movement, Run-key persistence), where the SigmaHQ packs carry most of the weight. ## Defects in REMN itself

These are not missing rules: a rule, a parser mapping or an engine is wrong, and fixing it recovers detections the rules already intend. Each was confirmed against the rows and the rule text, most by running the code.

1. **The server store drops about 73 fields the parser writes, so 65 pack rules give wrong answers in server-store cases.** The parser puts fields such as `accessList`, `objectServer`, `objectClass`, `application`, `startModule`, `destination`, `oldTargetUser`, `newTargetUser`, `contextInfo` at the top of each row, and the converted Sigma rules read them there. The browser keeps them; the DuckDB store has no column for them and drops them (`backend/services/store/casestore.py` EVENT_COLUMNS, `_arrow_table`), and the SQL fallback then reads a camel-case key from `data` that does not exist (`sqlfilter.py` resolve). A positive condition then never matches (CVE-2021-42287 computer-account rename, Default Domain GPO modification, Password Policy Enumerated, WMI consumer scripting), and a condition inside `not` always passes (an LSASS-excluding Kerberos rule fires 11 times; "Password Dumper Remote Thread in LSASS" fires on any remote thread into LSASS because `startModule = ''` is true on NULL). This is 7 of the 8 differences between the two engines found in this run. The public site, which runs the browser engine, is not affected. Fix: a column per parser field (or one JSON column for them), backfilled from `data`, and parity fixture rows that carry such fields.
2. **The SQL engine never matches IPv6 ranges in the case's internal IPs.** `sqlfilter._setting_condition` compiles only IPv4 networks as ranges and compares IPv6 networks such as `fe80::/10` as plain text, so an RDP logon from a link-local address counts as external on the server (win-rdp-logon-external). The browser is right. This is the eighth engine difference.
3. **Four core process-creation rules read only `processName`, which Sysmon rows never carry.** Sysmon process creation sets `image`; not one of the 1,491 Sysmon 1 rows in the library has `processName`. So on Sysmon data the core rules for encoded PowerShell, LOLBins with suspicious arguments, Office spawning a shell and execution from temp/download folders never fire (`win-powershell-encoded-command`, `win-lolbin-suspicious-commandline`, `win-office-spawns-shell`, `win-process-from-suspicious-path`); they work only on 4688. Fix: make those rules read `image` as well, or have the parser set `processName` from `Image` for Sysmon 1.
4. **The Sigma field `Data` maps to `dataList`, which the parser never sets.** It writes the joined list to `message` instead. 383 rows carry a Data list and none has `dataList`, so every converted rule on MSSQL, MsiInstaller and classic PowerShell events is dead in both engines: xp_cmdshell enabled (2 samples), MSI installed from a URL, the Emotet PowerShell 800 events.
5. **A `-` placeholder becomes an empty field, so rules that compare to `-` never match.** `evtx_parser._str()` turns `-` into null; all 33 logons with `WorkstationName: -` have no workstation. The RottenPotato / JuicyPotato rule (`workstation: '-'`) cannot fire.
6. **Access-list codes are not rendered.** `accessList` holds `%%4417`, not `WriteData`, so upstream rules written against the rendered name (svcctl and atsvc pipe writes over IPC$, desktop.ini) never match. One upstream rule already tests both spellings, which shows the intent.
7. **The converter turns "field is empty" on a field with two aliases into any-of instead of all-of.** `Image` maps to `image` or `processName`; "Image is empty" becomes "either is empty", which is always true on Sysmon rows, so filters built on it misfire. "Uncommon Child Process Of Conhost.EXE" cannot fire because of it; about 15 rules share the pattern.
8. **Core rule bugs.**
   - `win-remote-thread-injection` is titled "Sysmon 8 / 10" but only reads event ids 8 and 25, so process-hollowing handles (Sysmon 10, 0x1fffff) are not seen.
   - `win-registry-run-key` matches any key containing `\Services\`: 12 of its 22 firings rest on nothing else. Some are real service installs labelled as Run-key persistence; others are unrelated service settings such as the Background Activity Moderator (`\Services\bam\State\UserSettings\...`), LanmanServer shares and NullSessionPipes, which deserve rules of their own.
   - `win-bits-download` excludes allowed hosts by `raw|not_contains`, and every EVTX record's raw holds `schemas.microsoft.com`, so the rule can never fire on EVTX (0 of 278); BITS downloads from imgur and uguu.se went unflagged.
   - `win-credential-dumping` exempts every source image under System32, including powershell.exe, so reflective Invoke-Mimikatz opening LSASS with 0x1010 is missed.
9. **Older logs lack a field that newer Sysmon and Windows versions carry.** Sysmon before ParentUser (2 samples: RogueWinRM, the NetworkService token trick) and 4688 version 1 without a parent process name (WMI remote execution) leave "SYSTEM child of a service account" and "child of WmiPrvSE" undetectable. Filling the field at ingest from the parent's own row (ParentProcessGuid, or the creator process id) would recover them.
10. **Two upstream rules that would catch the spooler DLL tricks were skipped at import** because they are informational upstream (SpoolFool, CVE-2020-1030). Converting them at high severity when the loaded DLL is unsigned would close both.

## What the rules do not cover

The 54 missed and 32 partial samples blamed on a missing rule fall into a few groups; the appendix gives each sample and the rule that would close it.

- **Channels with no rules:** Microsoft-Windows-RPC ETW (PetitPotam, Zerologon calls), ProcessExitMonitor 3001 (LSASS dumped by SilentProcessExit), Netlogon 5805 (Zerologon), MSSQL 18456 and 15281, Program-Compatibility-Assistant 17 (a .cpl run from Downloads), Application-Experience 500 (shim persistence on osk/utilman), Winsock 1 (LSP install), DistributedCOM 10016 (failed DCOM lateral movement), RdpCoreTS 148 and 168 (BlueKeep scan, SharpRDP), TerminalServices 1149 from loopback (RDP tunnelling), Security 4826 (test signing / kernel debug), 4985 (process doppelgänging), 4703 (SeDebugPrivilege enabled), 4798/4799 (local group enumeration), 5142 (a share exposing C:\Windows\System32).
- **Correlations and thresholds:** BloodHound and PsLoggedOn seen as a burst of IPC$ pipe opens, SMB sweeps, pipe scans, Meterpreter `ps` as a burst of process opens, Kerberos spraying on 4771, SharpRDP sessions, PPID spoofing, remote scheduled-task creation.
- **Registry keys:** `__PSLockdownPolicy` (CLM disabled), PowerShell ExecutionPolicy, `NullSessionPipes`, new LanmanServer shares, SAM account records (RID hijack, account creation seen from lsass), IEAK PendingGPOs, the Update Orchestrator UScheduler, registry symbolic links, `Volatile Environment\SYSTEMROOT`, per-user COM `InprocServer32`, `Launcher.SystemSettings\shell\open\command`.
- **DLL loading:** phantom DLLs (cdpsgshims, WindowsCoreDeviceInfo, WptsExtensions), unsigned DLLs loaded by svchost or by auto-elevating binaries (sysprep/cryptbase), the RDP ActiveX loaded outside mstsc (SharpRDP).
- **Process lineage:** a browser spawning a shell (drive-by), svchost spawning a bare cmd (reverse shell) or a LOLBin (BITS notify command), renamed binaries recognisable by their PE description (regsvr32, cscript), an accessibility binary that is a shell, execution from `\\tsclient\`, inbound connections to explorer.exe (DCOM ShellWindows).
- **Tool names the packs spell differently:** `Akagi_64.exe` (the packs list Akagi64.exe), the kekeo tsssp pipe, SharpRDP, ProcessHerpaderping, Frida's injector.

## What to do first

1. Fix defects 3, 4, 5 and 8 (core rules on `image`, the `Data`/`dataList` mapping, `-` placeholders, the four core rule bugs). Each is small, each recurs across the library, and some of them currently produce findings that are wrong rather than missing.
2. Fix defect 1 before anyone relies on a server-store case: it silently changes 65 rules there. Add rows with those fields to the parity fixture so the two engines cannot drift again.
3. Fix the converter issues (6, 7) and re-import the packs; convert the two skipped spooler rules.
4. Then add rules by group, starting with the channels that have none and the Discovery correlations, which is where coverage is lowest.
5. Keep this run: making the harness a tool, and running the library in CI where endpoint protection does not interfere, turns these numbers into a regression check (the roadmap's "EVTX-ATTACK-SAMPLES in CI").

## Method and limits

- Detection means "on by default, in the browser engine", with default case settings: no admin or service accounts and no internal domains. A few rules would fire with those settings filled in; none of the misses above depends on it.
- Relevance was judged by reading each sample; it is a judgement, re-checked once by a second reviewer, not a label shipped with the library.
- Hayabusa was not run. On the public site it adds its own Sigma-based detections for EVTX, so the site's real coverage is somewhat higher than these numbers for REMN's own rules.
- The 5 "no signal" samples hold only events that any benign activity produces (one srvsvc pipe open, a routine machine-account secret update, RDP time-zone events, account changes with every attribute unset).
